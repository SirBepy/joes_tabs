## What went wrong (the cron post-mortem - Joe explicitly asked)

The `/cron-run` overnight schedule did NOT fire overnight. Root causes, in order:
1. **CronCreate downgraded `durable=true` to "session-only" in this environment.**
   `~/.claude/scheduled_tasks.json` was never written (only `scheduled_tasks.lock`
   exists). Session-only = lives in memory, dies when the session/PC stops.
2. **PC slept overnight.** A session-only cron is not an OS job, so sleep killed
   it. The only 2 ticks that fired happened ~12:23 and ~12:43 local (midday, when
   the machine was awake again), not overnight.
3. **Wrong window anyway.** Schedule was `2,22,42 5-13 * * *` = hours 05:00-13:00
   only (Joe had said "run at 5 AM"). That is a daytime window, never covered the
   real night.
4. **Tooling fought back during setup.** Batched tool calls kept cascade-cancelling:
   one failing Bash in a parallel block aborted every sibling call (including all
   CronCreate calls and git pushes). Worked around by doing ONE tool call per
   message and using a SINGLE recurring cron instead of N durable one-shots (a
   deviation from the skill, which compounded the fragility).

**Fix options for next time (Joe to choose):**

- OR keep local `/cron-run` but disable Windows sleep (`powercfg`) AND leave Claude
